# labkit

一个**项目结构骨架**。不是工具，不是框架，不跑任何判定。

它解决的问题只有一个：

> 一个项目由多个 AI（不同模型、不同 API、不同客户端）和人类交替推进，
> 上下文的丢失不应该等于知识的丢失。

labkit 的做法是把"该记住的东西"固定到一组**位置、语义和写入规则**上，
让任何能读文件、能写文件的 agent，换进来就能接手，且不依赖任何软件的记忆功能。

## 它是什么

- **一组文档**：定义目录结构、每个文件的含义、写入规则。
- **一套模板**：复制即用，附填写提示。
- **一个约定**：什么写哪里、写多长、追加还是覆盖。

## 它不是什么

| 不是 | 原因 |
|---|---|
| 不是 CLI / 数据库 / 服务 | 装了就在，没装就没了；换机器、多年后回看都会失效 |
| 不是自动记忆插件 | 只对单一客户端生效，恰好是本项目要避免的依赖 |
| 不是判定引擎 | 它记录"结论是什么、依据在哪"，不计算"结论是否正确" |
| 不是实验管理软件 | 队列、`batch.json`、训练脚本仍然归项目自己 |

## 四层模型

labkit 的核心是一个分层：不同层的**可信度**不同，所以**写入权限**也不同。

| 层 | 内容 | 谁写 | 可信度 |
|---|---|---|---|
| **意图层** | 问题、假设、设计、决定、断言 | agent 和人 | 主观，可能错 |
| **证据层** | 对产物的引用（目录、commit、哈希） | agent 和人 | 可核对 |
| **审计层** | git 历史、文件内容 | **不由 agent 写** | 不可伪造 |
| **交接层** | 当前状态、动作流水 | agent | 易过期 |

关键推论：**agent 自己写的记录，不能当作关于 agent 的证据**。
所以审计层必须由 git 承担，labkit 只负责引用它，不试图代替它。

## 结构

```text
<project>/
├── AGENTS.md              入口协议（跨工具标准）
├── CLAUDE.md              一行指针，给只认 CLAUDE.md 的客户端
├── CHARTER.md             要回答的一个问题 + 边界 + 完成标准（稳定）
├── STATE.md               当前状态交接卡（覆盖式，有上限）
├── LOG.md                 动作流水（追加式，有上限，超出归档）
├── DECISIONS.md           决定记录（追加式，supersede 不覆盖）
├── NOTES/
│   ├── BASE.md            已确立事实（有界，每条带来源）
│   ├── THINKING.md        未验证的假设（含推翻条件）
│   ├── DESIGN.md          实验/执行设计（先冻结再执行）
│   └── RUNS.md            执行记录（指向产物，不复制产物）
├── CLAIMS/                【科研档位，可选】
│   ├── INDEX.md           一行一条的断言索引
│   └── C001.md            单条断言：判据 + 证据 + 结论
└── archive/
    └── INDEX.md           归档流水的一行式索引
```

核心档位 = 去掉 `CLAIMS/`，其余全部适用。
科研项目加上 `CLAIMS/`，就能把"我认为"变成"有判据、有证据、可被否决"的记录。

## 采用方式

1. 复制 `templates/` 下的文件到新项目根目录。
2. 填 `CHARTER.md`（这是唯一需要认真想的一步）。
3. 填 `AGENTS.md` 里与该项目相关的部分（命令、约束）。
4. 在 `STATE.md` 写第一张交接卡。
5. 开始工作。之后只维护 STATE / LOG / NOTES。

详细规范见 `references/`：

- `structure.md` — 每个文件的用途、写入者、生命周期、长度上限
- `conventions.md` — 编号、链接、状态词、追加/覆盖、什么不该记
- `layering.md` — 四层模型与它为什么这样切

## 设计依据

三条不变量不是凭空来的：

1. **自述 ≠ 证据**。对九个前沿模型的评测里，最常见失败是 overclaiming（31.4%）；
   一个由 agent 自己撰写的记录，无法用来核查 agent 的结论。
2. **判据先于结果**。若"什么算成立"在跑完之后才写，就等于允许事后编造标准。
3. **追加，不覆盖**。结论变化本身是有价值的信息，抹掉它等于伪造历史。

labkit 只把这些变成**结构约束**，不做自动裁决——裁决属于项目自己的证据和 git 历史。

## 版本

`v0.1` — 结构与规范定稿，模板可用。判定机制、检索索引、迁移工具均**不在**本版范围。
