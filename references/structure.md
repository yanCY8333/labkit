# 结构规范

每个文件的**用途、写入者、生命周期、长度上限**。超出上限意味着这个文件该被拆分或归档，而不是继续加长。

## 完整树

```text
<project>/
├── AGENTS.md              入口协议
├── CLAUDE.md              指针
├── CHARTER.md             项目宪章
├── STATE.md               交接卡
├── LOG.md                 动作流水
├── DECISIONS.md           决定记录
├── NOTES/
│   ├── BASE.md            已确立事实
│   ├── THINKING.md        未验证假设
│   ├── DESIGN.md          设计
│   └── RUNS.md            执行记录
├── CLAIMS/                科研档位
│   ├── INDEX.md
│   └── C001.md
└── archive/
    └── INDEX.md
```

`CLAIMS/` 之外的文件是**核心档位**，任何项目都要有。
`CLAIMS/` 是**科研档位**：只有当你需要"断言 + 判据 + 证据"时才加。

## 文件语义

### AGENTS.md

| | |
|---|---|
| 写入者 | 人（一次性） |
| 生命周期 | 极少变；项目约定变了才改 |
| 上限 | 80 行 |
| 内容 | agent 开工该做什么、写日志的格式、项目特有的命令与约束 |

跨工具标准，Codex / Cursor / Copilot / OpenCode / Gemini CLI / Zed / Aider 等 30+ 工具会读。
不要在这里写项目知识——那是 CHARTER 和 NOTES 的事。

### CLAUDE.md

| | |
|---|---|
| 写入者 | 人（一次性） |
| 上限 | 3 行 |
| 内容 | `@AGENTS.md`，以及 Claude 专属的极少量指令 |

存在的原因：少数客户端只认 CLAUDE.md。它是指针，不是第二份协议——**两份协议必然分叉**。

### CHARTER.md

| | |
|---|---|
| 写入者 | 人（主导） |
| 生命周期 | **稳定**。只有"问题本身变了"才改，改时在 DECISIONS 留痕 |
| 上限 | 40 行 |
| 内容 | 要回答的一个问题、明确不回答的问题、完成标准、不可协商的约束 |

这是唯一值得慢慢想的一页。写不清楚，后面的 NOTES 会往四个方向散。

反模式：把进度、待办、结果写进 CHARTER。那些属于 STATE 和 NOTES。

### STATE.md

| | |
|---|---|
| 写入者 | 当前接手的 agent |
| 生命周期 | **易变**，覆盖式 |
| 上限 | 60 行 |
| 内容 | owner / updated / lease、目标、当前假设、最近一次运行、下一步、阻塞 |

覆盖是设计而非疏忽：交接卡的价值在于**短**。长了的交接卡没人读，等于没有。
历史在 LOG，不在 STATE 里堆积。

`owner` + `lease_until` 是**软锁**：只是告诉别人谁在动，不做强制。冲突时以 LOG 的写入顺序为准。

### LOG.md

| | |
|---|---|
| 写入者 | 所有 agent |
| 生命周期 | **追加**，到 40 条时把最旧的移入 `archive/` |
| 上限 | 40 条 + 3 行归档摘要 |
| 内容 | 一行一条：时间、agent、类型、动作、`out=` 产物路径 |

格式固定，便于 grep：

```text
2026-11-02 14:20 | claude/opus | R | 跑完 4 图 fine-only 对照  out=runs/fine_only/
```

归档规则：把最旧的条目按月份移入 `archive/YYYY-MM.md`，`archive/INDEX.md` 每批加一行摘要
（日期区间、条数、类型计数）。`LOG.md` 顶部保留最近 3 条归档摘要，永远不增长。

### DECISIONS.md

| | |
|---|---|
| 写入者 | 人主导，agent 可提议 |
| 生命周期 | **只增**，修正用 supersede |
| 上限 | 无硬上限，但每条 ≤ 6 行 |
| 内容 | 一个"以后不该再重新讨论"的选择 |

格式：

```markdown
## D007 · 采用单文件 vendor 而不是安装式 CLI
日期：2026-11-02 · 状态：生效 · supersedes：D003

决定：每个项目内嵌一份 labkit 规范，不依赖全局安装。
代价：修 bug 需要手动同步；换来的是项目自包含、多年后可读。
```

必须写**代价**。只写收益的决定记录没有信息量。

### NOTES/BASE.md

| | |
|---|---|
| 写入者 | 任何人，但每条必须已经结算 |
| 生命周期 | 增删皆可（事实会被推翻），推翻要留痕 |
| 上限 | 80 行 |
| 内容 | 当前已确立的事实，每条带来源 |

一行一事实，带状态标记：

```text
- ✅ [C002] 24L 在 full 上比 SIREN 高 4.4–4.9 dB（16图6骨干，20k）   来源：runs/natural_384/
- ◐ [C005] sparse 上最优容量随骨干变化                             来源：runs/layer_ablation/
- ❌ 固定 GT warp 可用                                              来源：experiments/closed_form/
```

状态：`✅ 已确立` / `◐ 初步` / `❌ 已排除` / `❓ 未验证`。

`❌` 条目**必须永久保留**——已排除的路是最值钱的知识，删掉就会有人重走。

### NOTES/THINKING.md

| | |
|---|---|
| 写入者 | agent 主导 |
| 生命周期 | 追加为主，假设被推翻时原地标 ❌ 并保留 |
| 上限 | 每条 ≤ 25 行，整体无硬上限但需按主题分节 |
| 内容 | 尚未验证的判断，**必须包含推翻条件** |

每条四段：现在相信什么 / 证据 / 反证 / 什么会推翻它。
没有"什么会推翻它"的条目不是假设，是观点，不该放这里。

### NOTES/DESIGN.md

| | |
|---|---|
| 写入者 | 人批准，agent 起草 |
| 生命周期 | 追加；已执行的设计不再修改，只追加结果指针 |
| 上限 | 每个设计 ≤ 80 行 |
| 内容 | 问题、假设、矩阵、对照、预算、指标、**判定规则**、威胁、命令 |

核心纪律：**判定规则写在执行之前**。跑完再改判定规则，整份设计作废。

### NOTES/RUNS.md

| | |
|---|---|
| 写入者 | 执行者 |
| 生命周期 | 追加 |
| 上限 | 每条 ≤ 15 行 |
| 内容 | 跑了什么、状态、产物路径、异常 |

**只引用产物，不复制产物。** 数字放在 `results.csv` 里，RUNS 只写"哪次跑、结果在哪、异常是什么"。

### CLAIMS/ （科研档位）

`INDEX.md`：一行一条，`ID | 一句话 | 状态 | 证据`。
`Cxxx.md`：单条断言，≤ 60 行。

必须包含：断言、**判据（创建时写死）**、所需样本量、证据链接、结论。
结构见 `templates/CLAIMS/C000.md`。

`created` 日期与 `criteria` 的先后顺序是这个文件唯一的价值来源。判据可以在结论之后写，那它就是装饰。

## 可选扩展

以下几种情况可以加文件，加之前先在 DECISIONS 记一笔：

| 场景 | 建议 |
|---|---|
| 数据说明复杂 | `NOTES/DATA.md`，每条数据带路径、哈希、许可 |
| 协议很长且反复引用 | `NOTES/PROTOCOL.md`，DESIGN 只引用不复制 |
| 多人多 agent 并行 | 每人一个 `STATE.<agent>.md`，根 STATE 只做索引 |
| 需要外部检索 | 另建索引层，**不要把索引塞进上面任何文件** |
